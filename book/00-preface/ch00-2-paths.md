# 0.2 三条阅读路径

> 基准：pi `b79e4cc8` (v0.84.4)　·　[版本表](../../research/BASELINE.md)　·　[参与指南](../../CONTRIBUTING.md)

全书 37 章，章号全局连续。但没有人需要从第 1 章读到第 37 章。

本书的结构是**两条线交织**：

- **纵线**（第一、二、四部分）：从选型到交付 —— *你要做什么*
- **横线**（第三、六部分）：pi 的基线 + 各家的选择 —— *别人已经做了什么*
- 第五部分是**原理层**，随时可查，也可以当独立读物

---

## 路径 A · 产品经理 / 技术决策者

**目标**：判断该不该上、上了要投多少、能对用户承诺什么。

| 顺序 | 读 | 拿到什么 |
| --- | --- | --- |
| 1 | [第 2 章](../01-choosing/ch02-what-is-pi.md) Pi 是什么 | 794 行内核 + 6 万行产品层，复杂度重心在哪 |
| 2 | [第 4 章](../01-choosing/ch04-capability-boundary.md) 能力边界 | 23 项能力盘点，哪些是"论证过不做" |
| 3 | [第 5 章](../01-choosing/ch05-should-you-use-pi.md) 该不该用 Pi | 与 Claude Agent SDK / 直接调 API / fork codex 的取舍 |
| 4 | [第 6 章](../01-choosing/ch06-cost-and-effort.md) 成本与投入 | token 经济学 + 从各家 diff 规模反推的工程量 |
| 5 | 第三部分**各章 X.1 与 X.2 两节** | 每个策略问题上 pi 给了什么、各家补了什么 |
| 6 | [第 22 章](../04-shipping/ch22-preflight.md) 上线前必补清单 | 交付给非专家用户之前的硬门槛 |

**跳过**：第二部分（动手）、第五部分（原理）。需要时再回来。

**如果只有 20 分钟**：第 4 章 + 第 22 章。前者告诉你边界，后者告诉你代价。

## 路径 B · 开发者（要动手做一个）

**目标**：跑起来、改得动、交付得了。

| 顺序 | 读 | 拿到什么 |
| --- | --- | --- |
| 1 | [第 7 章](../02-getting-started/ch07-hello-pi.md) 30 分钟跑通 | 装上、看懂它在做什么 |
| 2 | [第 8 章](../02-getting-started/ch08-extension-model.md) 扩展系统的心智模型 | 为什么是 TS 模块而不是声明式清单 |
| 3 | [第 9 章](../02-getting-started/ch09-api-lookup.md) 任务 → API 反查表 | **查着用**，不要通读 |

**目标**：看 794 行内核是怎么被设计出来的，以及五支团队的选择差异说明了什么。

| 顺序 | 读 | 拿到什么 |
| --- | --- | --- |
| 1 | 第五部分全部（26–30） | Agent Loop 三层切分、双队列、上下文四条硬规则、工具执行的坑、v1/v2 双运行时 |
| 2 | [第 15 章](../03-policy-layer/ch15-mechanism-not-policy.md) 机制 vs 策略 | 一条贯穿六个领域的设计线，以及它的三处裂缝 |

| 4 | [`research/pi/`](../../research/pi/) | 研究底稿本身。比正文密度高得多，全部带行号 |

这条路径可以直接从第五部分开始，不需要装过 pi。

**如果只读一章**：[第 28 章 上下文工程四条硬规则](../05-internals/ch28-context-engineering.md)。四条规则各自都是"看起来可以更聪明，但聪明写法会在某个边界上错得很难查"的结果，是全书信息密度最高的一章。
